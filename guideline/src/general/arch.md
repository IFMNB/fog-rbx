# Architecture

Архитектура проекта построена вокруг единого базового класса `object`. Все остальные объекты являются его наследниками и расширяют существующее поведение без изменения принципов работы всей системы.

При написании нового функционала рекомендуется использовать уже существующие базовые классы в зависимости от требуемого жизненного цикла объекта.

## object

`object` является фундаментом всей архитектуры проекта.

Любой объект проекта, обладающий собственным поведением, должен наследоваться именно от него.

`object` предоставляет общий интерфейс для всей системы:

* создание экземпляров;
* определение типа объекта;
* проверку принадлежности к типу;
* обход дерева наследования;
* клонирование;
* создание неизменяемых объектов;
* получение статистики созданных экземпляров.

Данный класс вводит единое понятие объекта во всем проекте и используется как общий базовый тип.

## Record

`Record` является наследником `object`.

Данный класс следует считать аналогом неизменяемой структуры (`struct`).

Объекты данного типа предназначены исключительно для хранения данных и не предполагают сложного жизненного цикла.

Создание новых значений считается дешевой операцией. Вместо изменения существующего состояния рекомендуется создавать новый экземпляр `Record`.

Каждый созданный экземпляр учитывается внутренней статистикой класса.

## Disposable

`Disposable` является наследником `object`.

Данный класс предназначен для объектов, имеющих собственный жизненный цикл.

Экземпляры данного типа могут:

* быть освобождены;
* ожидать освобождения;
* запрещать собственное освобождение;
* уведомлять подписчиков о завершении жизненного цикла.

Если объект должен существовать ограниченное время или владеть освобождаемыми ресурсами, рекомендуется наследовать именно `Disposable`.

Освобождение объекта производится исключительно средствами данного класса.

## Service

`Service` является наследником `object`.

Сервис представляет собой глобальный объект, существующий в единственном экземпляре в рамках своей области выполнения.

Сервисы предназначены для организации общей логики приложения и предоставления функциональности другим объектам.

Создание экземпляров сервиса извне запрещено.

Жизненный цикл сервиса контролируется архитектурой проекта.

При необходимости взаимодействия различных частей проекта рекомендуется использовать существующие сервисы вместо создания дополнительных глобальных состояний.

## enum

`enum` является наследником `object`.

Данный класс используется для создания именованных наборов констант.

Каждое значение перечисления получает собственный числовой идентификатор, вычисляемый на основании строки.

Класс предоставляет общий интерфейс для:

* получения списка всех значений;
* получения количества элементов;
* поиска имени по значению;
* учета количества созданных перечислений.

Использование магических чисел вместо `enum` не рекомендуется.

# Наследование

Все классы архитектуры строятся относительно базового `object`.

```text
object
├── Record
├── Disposable
├── Service
└── enum
```

Наследование должно отражать назначение объекта, а не его местоположение в файловой системе.

Если новый тип объекта не обладает собственным жизненным циклом, но представляет самостоятельную сущность проекта, рекомендуется наследоваться непосредственно от `object`.

Если объект хранит только данные, рекомендуется использовать `Record`.

Если объект требует освобождения ресурсов или уничтожения, рекомендуется использовать `Disposable`.

Если объект представляет глобальную функциональность проекта, рекомендуется использовать `Service`.

Если требуется описать набор констант, рекомендуется использовать `enum`.

# Расширение архитектуры

Новые классы рекомендуется наследовать от наиболее близкого по назначению базового класса.

Не рекомендуется дублировать уже существующее поведение базовых классов.

Если требуемое поведение отсутствует ни в одном из существующих базовых классов, допускается наследование непосредственно от `object` с последующим добавлением необходимого функционала.

Изменение поведения базовых классов считается архитектурным изменением и должно производиться только при необходимости развития всей системы.

# Events Architecture

Подсистема событий отвечает за обмен сообщениями между объектами проекта.

Каждый объект самостоятельно определяет, какие события он предоставляет наружу, а также какие данные могут сопровождать данные уведомления.

## Event

`Event` является наследником `Disposable`.

Событие представляет собой объект, управляющий списком подписчиков и их уведомлением.

Данный класс предоставляет единый механизм подписки независимо от источника возникновения события.

В обязанности `Event` входит:

* регистрация новых подписчиков;
* удаление существующих подписчиков;
* отправка уведомлений;
* ожидание следующего уведомления;
* управление жизненным циклом соединений.

Само событие не содержит игровой логики и используется исключительно как диспетчер уведомлений.

## Face

`Face` является наследником `Disposable`.

`Face` представляет собой публичный интерфейс события.

Данный объект предоставляет только методы взаимодействия с событием и скрывает внутреннюю реализацию `Event`.

Через `Face` допускается:

* подписка на событие;
* одноразовая подписка;
* ожидание следующего уведомления.

Создание уведомлений через `Face` невозможно.

Использование `Face` рекомендуется во всех случаях, когда событие публикуется наружу.

## Connection

`Connection` является наследником `Disposable`.

Соединение представляет собой соглашение между событием и его подписчиком.

Каждое соединение соответствует одной зарегистрированной функции обратного вызова.

Соединение отвечает за:

* хранение обработчика;
* контроль собственного состояния;
* разрыв подписки;
* автоматическое освобождение ресурсов.

После разрыва соединения уведомления более не доставляются.

## ConnectionState

`ConnectionState` является перечислением состояний соединения.

На данный момент поддерживаются следующие состояния:

* `Alive` — соединение активно;
* `Dead` — соединение разорвано.

Данное перечисление используется системой событий для определения дальнейшего жизненного цикла соединения.

# Values Architecture

Подсистема значений предназначена для хранения изменяемых данных и их синхронизации с экземплярами Roblox.

Каждое значение может сопровождаться собственными событиями изменения и дополнительными метаданными.

## Value

`Value` является наследником `Disposable`.

Данный класс представляет изменяемое значение, принадлежащее объекту.

Помимо хранения данных `Value` предоставляет механизм уведомления об их изменении.

В обязанности класса входит:

* хранение текущего значения;
* изменение значения;
* уведомление подписчиков;
* синхронизация связанных объектов;
* работа с дополнительными атрибутами.

`Value` используется как основной способ представления изменяемого состояния внутри архитектуры.

## Attribute

`Attribute` является наследником `Disposable`.

Атрибут представляет собой оболочку над атрибутом экземпляра Roblox (`Instance Attribute`).

Объект отвечает за сопровождение конкретного атрибута и предоставляет единый интерфейс взаимодействия с ним.

В обязанности `Attribute` входит:

* получение текущего значения;
* изменение значения;
* отслеживание изменений экземпляра;
* уведомление подписчиков;
* синхронизация состояния объекта и экземпляра.

Если данные должны существовать непосредственно внутри `Instance`, рекомендуется использовать `Attribute`.

# Наследование

Подсистема событий построена относительно следующих базовых классов.

```text
Disposable
├── Event
├── Face
└── Connection
```

Состояния соединений описываются отдельным перечислением.

```text
enum
└── ConnectionState
```

Подсистема хранения данных построена независимо от системы событий.

```text
Disposable
├── Value
└── Attribute
```

При этом `Value` и `Attribute` могут использовать объекты `Event`, `Face` и `Connection` для уведомления об изменении собственного состояния.

# Расширение архитектуры

Если новому объекту требуется уведомлять другие части системы о происходящих изменениях, рекомендуется использовать `Event`.

Если событие должно публиковаться как часть публичного API класса, рекомендуется предоставлять только объект `Face`.

Если требуется хранить изменяемое состояние объекта, рекомендуется использовать `Value`.

Если значение должно быть связано с атрибутом экземпляра Roblox, рекомендуется использовать `Attribute`.

Изменение принципов работы системы событий или хранения значений считается архитектурным изменением и должно производиться только при необходимости развития всей системы.

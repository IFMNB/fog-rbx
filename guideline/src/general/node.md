# Node Architecture

Данный раздел описывает архитектуру объектов, взаимодействующих с экземплярами Roblox и их жизненным циклом.

Основной задачей данной части архитектуры является сопровождение объектов на протяжении всего времени существования соответствующего `Instance`, а также организация обработки обновлений внутри игрового мира.

## Node

`Node` является наследником `Disposable`.

Нода представляет собой объект, связанный с конкретным экземпляром Roblox (`Instance`).

После инициализации объект становится владельцем логики сопровождения данного экземпляра и предоставляет единый интерфейс для взаимодействия с ним.

В обязанности `Node` входит:

* привязка к `Instance`;
* сопровождение жизненного цикла экземпляра;
* синхронизация атрибутов;
* уведомление об изменениях;
* хранение связанных данных;
* автоматическое освобождение после уничтожения экземпляра.

Инициализация ноды выполняется только один раз посредством метода `:initiate()`.

После завершения инициализации экземпляр считается полностью готовым к дальнейшей работе.

## Processor

`Processor` является наследником `Node`.

Процессор представляет собой специализированную ноду, принимающую участие в выполнении игрового цикла.

В отличие от обычной `Node`, процессор обладает собственными стадиями обработки и может выполнять пользовательский код во время работы приложения.

Класс предоставляет следующие виртуальные методы:

* `:ready()`;
* `:process()`;
* `:simulation()`.

Переопределение данных методов является основным способом написания игровой логики.

Частота обработки определяется самим процессором и может отличаться от остальных объектов системы.

Процессоры используются для объектов, которым требуется постоянное выполнение вычислений.

## RuntimeVariant

`RuntimeVariant` является перечислением, определяющим способ выполнения процессора.

Каждое значение описывает, в каком окружении допускается выполнение объекта.

На данный момент существуют следующие варианты:

* `Inherit` — использовать настройки родительской системы выполнения;
* `Synchro` — выполнять только в синхронном режиме;
* `Parallel` — выполнять только в параллельном режиме;
* `Disabled` — полностью отключить выполнение.

Перечисление используется системой выполнения процессоров и не изменяется во время работы объекта.

## NodeNotificationType

`NodeNotificationType` является перечислением служебных уведомлений, отправляемых нодой.

Данные уведомления используются для передачи событий, не требующих создания отдельных объектов `Event`.

На данный момент поддерживаются следующие уведомления:

* `ValueChanged`;
* `NewValue`;
* `NewLazyValue`;
* `Destroyed`.

Подписчики самостоятельно определяют необходимость обработки конкретного уведомления.

# Наследование

Все объекты данной подсистемы строятся относительно базовой `Node`.

```text
Disposable
└── Node
    └── Processor
```

Служебные перечисления используются независимо от дерева наследования.

```text
enum
├── RuntimeVariant
└── NodeNotificationType
```

# Расширение архитектуры

Если новый объект должен сопровождать экземпляр Roblox на протяжении его существования, рекомендуется наследоваться от `Node`.

Если объекту требуется участие в игровом цикле и регулярное выполнение пользовательского кода, рекомендуется наследоваться от `Processor`.

Новые перечисления рекомендуется создавать только в случаях, когда набор возможных значений является фиксированным и заранее известен.

Изменение жизненного цикла `Node` или порядка выполнения `Processor` считается архитектурным изменением и должно производиться только при необходимости развития всей системы.

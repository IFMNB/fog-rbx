# Support

Before asking for help, make sure you are using the latest version of the project and check the documentation and existing issues.

Map:

Bug           → Issue / Bug Report
Feature       → Issue / Feature Request
Question      → Discussions
Security      → SECURITY.md
Contribution  → CONTRIBUTING.md

## Bug reports

If you found behavior that appears to be a bug, open a GitHub Issue using the **Bug Report** template.

Include:

* A clear description of the problem
* Steps to reproduce it
* Expected behavior
* Actual behavior
* Roblox Studio version
* Project/package version
* Relevant error messages, logs, or code

Do not report undocumented or intentionally unsupported behavior as a bug without first checking the project documentation.

## Feature requests

For new functionality or API changes, open an Issue using the **Feature Request** template.

Describe:

* What you want to add or change
* Why the feature is useful
* The expected API or behavior
* Any relevant implementation considerations

For large architectural changes, discussion should happen before submitting a pull request.

## Questions

For usage questions, API clarification, or help understanding the project, use GitHub Discussions instead of opening an Issue.

Before asking, check:

* Documentation
* Existing Issues
* Existing Discussions
* Examples in the repository

## Security issues

Do not report security vulnerabilities through public Issues or Discussions.

See `SECURITY.md` for the supported security reporting process.

## Pull Requests

Contributions are welcome.

Before opening a pull request:

* Make sure existing tests pass
* Add or update tests where appropriate
* Run the project's type checking and linting tools
* Keep unrelated changes out of the pull request
* Describe the motivation and implementation clearly

See `CONTRIBUTING.md` for the contribution guidelines.
